## FACT — 已验证缺陷及证据

- [services/indexer/index.ts:203](https://github.com/build-on-sol/Provena/blob/26a03ba078aec39eabdadf4d9f259ae08cc72533/services/indexer/index.ts#L203) 忽略精确运行时标记 `Log truncated`；L233 仅检查调用栈平衡及曾出现协议 invocation。L189 随后提交事件与 checkpoint，L191 标为 SYNCED。
- [Agave 2.3.0 collector](https://github.com/anza-xyz/agave/blob/v2.3.0/log-collector/src/lib.rs#L25) 丢弃超限日志并写入该标记，但该次不增加 bytes_written；之后更短的日志仍可保留。所以“调用栈完整”不能证明“事件日志完整”。
- 本轮独立复现使用本 SHA 实际编译的 RpcEventPoller、web3.js 1.99.0 的实际 JSON-RPC 解码和按上述 collector 实现构造的日志。正常日志记录 1 个 TipReceived；截断日志记录 0 个，二者都推进 checkpoint 并显示 SYNCED；截断后再次 poll 返回 0，事件仍缺失。
- 最小 RPC 回归日志如下；使用既有 rawTransaction fixture，让签名 finalized、meta.err=null、消息实际调用 Provena。未修复基线会返回零事件且 checkpoint 前进；修复后必须拒绝。正常对照使用 fixture.logs(100)。

```text
Program Fg6PaFpoGXkYsidMpWxTWqkZ86H8vFnafnHCW3Yj6nD invoke [1]
Program log: Instruction: Tip
Log truncated
Program Fg6PaFpoGXkYsidMpWxTWqkZ86H8vFnafnHCW3Yj6nD consumed 30000 of 200000 compute units
Program Fg6PaFpoGXkYsidMpWxTWqkZ86H8vFnafnHCW3Yj6nD success
```

- [现有回归:185](https://github.com/build-on-sol/Provena/blob/26a03ba078aec39eabdadf4d9f259ae08cc72533/services/indexer-rpc.test.ts#L185) 覆盖未知事件和缺失末尾 success，遗漏了“截断标记 + 完整调用栈”。
